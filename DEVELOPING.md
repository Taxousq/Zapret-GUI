# Zapret GUI — разработка
Техническая документация: запуск из исходников, сборка, выпуск релиза, внутреннее устройство.
Пользовательская инструкция — в [README.md](README.md).

---

## Быстрый старт (из исходников)


1. Скачайте или склонируйте проект:

   ```bat
   git clone <адрес-репозитория>
   cd Zapret+GUI
   ```

2. Запустите `start.bat` — он создаст `venv`, поставит зависимости и запустит
   приложение:

   ```bat
   start.bat
   ```

   > В **PowerShell** (и в Windows Terminal, где PowerShell стоит по умолчанию)
   > текущую папку нужно указывать явно — `.\start.bat`, иначе PowerShell ищет
   > программу в `PATH` и не находит её. В `cmd.exe` достаточно `start.bat`.
   > То же самое касается `.\build.bat`.

3. Если запрет не найден, откроется **мастер первого запуска** (см. следующий
   раздел). Для управления службой запустите `start.bat` правым кликом →
   «Запуск от имени администратора».

### Что делает `start.bat`

```bat
python -m venv venv                       :: создаёт venv (только если его ещё нет)
call venv\Scripts\activate.bat            :: активирует его
python -m pip install -r requirements.txt :: ставит зависимости
python main.py                            :: запускает приложение
pause
```

Ручной вариант тех же шагов:

```bat
python -m venv venv
venv\Scripts\activate
python -m pip install -r requirements.txt
python main.py
```

> `pip` вызывается только как `python -m pip`: если Python поставлен из Microsoft
> Store, отдельной команды `pip` в `PATH` может не быть, а `python -m pip` работает
> всегда.

Ставятся **четыре** зависимости: `PyQt6>=6.6.0`, `PyQt6-Charts>=6.6.0` (график
пинга на дашборде «Обзор»), `requests>=2.31.0` и `psutil>=5.9.0` (проверка
процесса в разделе «TG WS Proxy»). Полный список — в `requirements.txt`.
**`psutil` необязателен для запуска**: без него приложение работает, а раздел
«TG WS Proxy» показывает «неизвестен (psutil не установлен)». Без
`PyQt6-Charts` карточка «ПИНГ» вместо графика показывает подсказку об установке.

## Запуск


```bat
.\start.bat          :: из исходников: venv + зависимости + main.py
python main.py       :: если зависимости уже стоят
dist\ZapretGUI.exe   :: собранная версия
```

Для управления службой нужны **права администратора**. Без них окно откроется,
статус службы будет виден, но команды старта/остановки и установки стратегии
завершатся ошибкой «Отказано в доступе» — приложение покажет соответствующую
подсказку. Запуск от имени администратора:

```bat
:: правый клик по «Командная строка» → «Запуск от имени администратора»
cd /d D:\Coding\Zapret+GUI
.\start.bat
```

Разделу **«Обход (WARP)»** права администратора не нужны: он только вызывает
`warp-cli` уже работающей службы Cloudflare WARP и ничего не пишет в системные
файлы.

Закрытие окна **не завершает приложение** — оно сворачивается в трей
(то же делает кнопка «В трей» в шапке). Полный выход — пункт «Выход» в
контекстном меню иконки в трее (двойной клик по иконке показывает окно).

## Сборка


Сборка состоит из двух шагов: `build.bat` собирает папку `dist\ZapretGUI`
(`ZapretGUI.exe` + `_internal`, режим PyInstaller onedir), затем
`installer.iss` пакует её в установщик Inno Setup
(`Output\ZapretGUI-Setup-X.Y.Z.exe`). Ниже — оба шага подробно, а в конце —
как выпустить релиз для автообновления.

> **Сборка возможна только на Windows.** PyInstaller **не** кросс-компилирует:
> собрать exe под Windows с Linux/macOS нельзя, а 32-битный exe — только из
> 32-битного Python. Агент Harness (в песочнице без Windows) exe не собирает:
> он готовит только файлы сборки, а саму сборку выполняет пользователь на
> своём ПК.

### Автоматически: `build.bat`

```bat
build.bat
```

В PowerShell:

```powershell
.\build.bat
```

Скрипт делает всё сам:

```bat
python -m pip install -r requirements.txt
python -m pip install pyinstaller
python -m PyInstaller --clean --noconfirm zapret-gui.spec
pause
```

После сборки скрипт сам проверяет, что появился `dist\ZapretGUI\ZapretGUI.exe`, и печатает
`[OK] Build complete`. Если шаг упал, печатается `[ERROR]` с пояснением и окно
**не** закрывается — лог можно прочитать.

> Все сообщения в `build.bat` и `start.bat` — **на английском**. Это сделано
> намеренно: кириллица в `.bat`-файле ломает разбор команд `cmd.exe` при
> не-UTF-8 кодовой странице консоли (команда `python` может превратиться в
> `hon`). Оба файла сохранены в UTF-8 **без BOM** и начинаются с
> `@echo off` / `chcp 65001 >nul` / `setlocal`.

Результат — папка **`dist\ZapretGUI`**: `ZapretGUI.exe` (GUI без окна консоли) и
`_internal` с зависимостями. Поставка копируется целиком: распаковки при
запуске нет, поэтому старт быстрый и нет ошибки «Failed to load Python DLL».

### Вручную

```bat
python -m pip install -r requirements.txt
python -m pip install pyinstaller
python -m PyInstaller --clean --noconfirm zapret-gui.spec
```

### Что внутри `zapret-gui.spec`

| Параметр | Значение | Зачем |
|---|---|---|
| `name` | `ZapretGUI` | Имя папки поставки: `dist\ZapretGUI\ZapretGUI.exe` |
| `onedir` | `EXE(exclude_binaries=True)` + `COLLECT` | Без распаковки в `_MEI`: `python313.dll` лежит в `_internal` рядом с exe, поэтому нет ошибки «Failed to load Python DLL» при запуске сразу после установки |
| `console` | `False` | GUI-приложение, консоль не нужна |
| `icon` | `assets/icon.ico` | Если файла нет — строка игнорируется, сборка идёт с иконкой PyInstaller |
| `hiddenimports` | `['PyQt6.QtCharts', 'PyQt6.QtSvg']` | **Обязательно**: `QtCharts` подключается динамически (график пинга), без него exe упадёт при импорте |
| `datas` | `[]` | Папка запрета **не** включается в поставку — она скачивается отдельно |
| `upx` | `True` | Сжатие бинарников (если UPX есть в `PATH`; иначе шаг пропускается) |
| `excludes` | `tkinter`, `unittest`, `pydoc` | Уменьшают размер поставки |

Чтобы у exe была своя иконка, положите `assets/icon.ico` (размер 256×256) —
`zapret-gui.spec` подхватит файл автоматически.

### Создание установщика (Inno Setup)

1. Соберите exe: `.\build.bat` — должна появиться папка `dist\ZapretGUI` со `ZapretGUI.exe` и `_internal`;
2. Установите **Inno Setup 6**: <https://jrsoftware.org/isdl.php>;
3. Откройте `installer.iss` в Inno Setup Compiler и нажмите **Compile (F9)**;
4. Готовый установщик появится в `Output\ZapretGUI-Setup-1.0.1.exe`.

Что делает `installer.iss`:

* ставит папку поставки (`ZapretGUI.exe` + `_internal`) в `{autopf}\Zapret GUI`
  (обычно `C:\Program Files\Zapret GUI`);
* создаёт ярлык в меню Пуск и (по чекбоксу) на рабочем столе;
* добавляет запись в «Программы и компоненты» с деинсталлятором;
* предлагает запустить приложение после установки;
* папку запрета **не** ставит — её скачивает сам GUI при первом запуске;
* `CloseApplications=yes` и `RestartApplications=yes` — установщик сам закрывает
  работающий `ZapretGUI.exe` и запускает его заново, поэтому обновление
  «поверх» проходит без ошибки «файл занят другим процессом».

Версия установщика задана в `installer.iss` (`#define MyAppVersion "1.0.1"`) —
держите её в соответствии с `APP_VERSION` в `config.py`.

> **`AppId` (GUID) менять нельзя.** По нему Inno Setup узнаёт уже
> установленное приложение: с новым GUID установщик поставит вторую копию
> рядом, а не обновит существующую — и автообновление сломается.

> Агент Harness Inno Setup не запускает: он только пишет `.iss`-скрипт, сборку
> установщика выполняет пользователь.

### Как выпустить релиз (для автообновления)

Автообновление ищет в **последнем** релизе ассет с `Setup` и `.exe` в имени,
поэтому порядок такой:

1. поднимите версию в двух местах: `APP_VERSION` в `config.py` и
   `MyAppVersion` в `installer.iss` (например, `1.0.1` → `1.0.2`);
2. соберите поставку (`.\build.bat`) и установщик (`installer.iss` → F9);
3. создайте на GitHub релиз с тегом вида **`v1.0.2`** (префикс `v` не мешает:
   приложение срезает его перед сравнением версий). Пометьте релиз как
   *Latest release* — API `/releases/latest` отдаёт именно последний по дате,
   а не «помеченный» вручную;
4. приложите к релизу файл **`ZapretGUI-Setup-1.0.2.exe`** — без него
   обновление не предлагается (в журнал пишется предупреждение);
5. опишите изменения в теле релиза: этот текст показывается в диалоге
   обновления как «Что нового».

Проверка: на установленной `1.0.1` баннер «Доступна версия 1.0.2 → Открыть»
должен появиться в течение суток или сразу — по кнопке «Проверить обновление»
в карточке «Интерфейс (Zapret GUI)» раздела «Обновление».

## Portable-версия (флешка)


Portable-режим не требует установки и не пишет в реестр Windows: настройки и
журнал лежат рядом с exe.

**Вариант 1 — руками:**

1. соберите поставку: `.\build.bat`;
2. создайте папку (например, на флешке) и положите туда **всю** папку `dist\ZapretGUI`;
3. положите туда же файл `portable.flag` — можно взять готовый
   `portable.flag.example` и переименовать его (содержимое значения не имеет,
   важен сам факт наличия файла);
4. запустите `ZapretGUI.exe`.

**Вариант 2 — portable-установщик:**

```bat
iscc /dPORTABLE installer.iss
```

Такой установщик не требует прав администратора (`PrivilegesRequired=lowest`),
кладёт `portable.flag` рядом с exe и предлагает папку установки на выбор.

**Что даёт portable-режим:**

* настройки — в `config.ini` рядом с exe (не в реестре);
* журнал — в `logs\zapret-gui.log` рядом с exe (не в `%LOCALAPPDATA%`);
* папку с запретом можно положить рядом: `ZapretGUI.exe` + `zapret\`
  (автопоиск проверяет эту папку тоже) — тогда вся связка живёт на флешке.

Итоговая структура portable-сборки:

```
ZapretGUI.exe        # само приложение
portable.flag        # маркер portable-режима
zapret\              # папка запрета (по желанию; можно указать вручную в GUI)
config.ini           # настройки (создаётся при первом запуске)
logs\                # журнал (создаётся при первом запуске)
```

### Интерфейс и темы

Страницы не знают друг о друге: они сообщают о действиях сигналами, а фоновые
операции запускает главное окно (у него же — трей, статус-бар и общий статус).
Логика запрета целиком осталась в `core/*`.

Цвета берутся из активной темы (`gui/theme.py`): тёмная — по умолчанию, светлая
включается кнопкой в шапке. Выбор сохраняется в `QSettings("ZapretGUI", "Theme")`.
Иконки разделов рисуются кодом (`gui/icons.py`), PNG-файлов в проекте нет.

### Настройки

| Что | Где | Ключ |
|---|---|---|
| Путь к папке запрета | `QSettings("ZapretGUI", "Paths")` | `zapret_path` |
| Путь к TG WS Proxy | `QSettings("ZapretGUI", "Paths")` | `tgws_path` |
| Тема | `QSettings("ZapretGUI", "Theme")` | `theme` |
| Дата последней загрузки списка РФ (WarpBypass) | `QSettings("ZapretGUI", "Warp")` | `last_bypass_download` |
| Проверять обновления при запуске | `QSettings("ZapretGUI", "Updates")` | `check_on_startup` |
| Размер и позиция окна | `QSettings("ZapretGUI", "ZapretGUI")` | `geometry` |

Все настройки создаются через `core/settings.py`, который описывает **пять
областей**: `Paths`, `Theme`, `Warp`, `Updates`, `ZapretGUI`. В portable-режиме
они уезжают в `config.ini` рядом с exe: формат INI задаётся явно, потому что
конструктор `QSettings(organization, application)` всегда пишет в реестр.

## Автообновление


GUI обновляет сам себя через **GitHub Releases** репозитория
`Taxousq/Zapret-GUI` — установщиком, который лежит в ассетах релиза.

Как это работает:

1. приложение спрашивает у GitHub последний релиз
   (`https://api.github.com/repos/Taxousq/Zapret-GUI/releases/latest`);
2. версия из релиза (`tag_name`, например `v1.0.2`) сравнивается с текущей
   (`config.APP_VERSION`) — **как числа, а не как строки**, поэтому `1.10.0`
   старше `1.9.0` не считается;
3. если версия новее, в шапке окна появляется баннер
   «Доступна версия X.Y.Z → Открыть» (версии равны — баннера нет). Баннер
   умеет показывать **три варианта**, потому что обновление запрета проверяется
   там же:
   * «Доступна версия X.Y.Z» — обновление только GUI;
   * «Доступно обновление запрета» — обновление только запрета;
   * «Доступны обновления: интерфейс X.Y.Z и запрет» — оба сразу;
4. по клику открывается раздел **«Обновление»** — там карточка
   «Интерфейс (Zapret GUI)» с текущей и доступной версиями и кнопкой
   **«Обновить»**. Она открывает диалог обновления: список изменений из
   релиза, кнопки **«Скачать и установить»**, **«Позже»** и
   **«Открыть на GitHub»**;
5. установщик скачивается в `%TEMP%\ZapretGUI-update\` (с прогресс-баром и
   проверкой, что файл — `.exe` больше 1 МБ), после чего приложение
   предупреждает: «Приложение будет закрыто, установщик запустится
   автоматически»;
6. установщик запускается отдельным процессом (переживает закрытие GUI), а
   приложение завершается. Если запустить установщик не удалось — приложение
   **не** закрывается и показывает ошибку.

Когда проверяется:

* **при запуске** — через 5 секунд после старта, тихо: без интернета или при
  исчерпанном лимите запросов GitHub ничего не показывается, всё уходит в журнал;
* **раз в сутки** — пока приложение работает (таймер на 24 часа);
* **по кнопке** «Проверить обновление» в карточке «Интерфейс (Zapret GUI)»
  раздела «Обновление»: здесь ошибки уже показываются («Не удалось проверить
  обновления», «Превышен лимит запросов GitHub, попробуйте позже»);
* чекбокс **«Проверять обновления при запуске»** (там же, в карточке
  интерфейса) отключает автоматические проверки — сохраняется в
  `QSettings("ZapretGUI", "Updates")`, ключ `check_on_startup`.

Что важно знать:

* обновляется **только установленная** версия. Portable-сборка автоматически
  не обновляется: карточка покажет «Portable-версия не обновляется
  автоматически, скачайте новую с GitHub»;
* обновление запрета (Flowseal) и Cloudflare WARP — соседние карточки того же
  раздела, но **другие механизмы**: запрет распаковывается в свою папку, WARP
  обновляет себя сам;
* установщик обновляет приложение **поверх** старой версии: `AppId` в
  `installer.iss` между версиями не меняется;
* прерывание скачивания (обрыв сети) не оставляет мусора: неполный файл
  удаляется, и его можно скачать заново.

## Вкладка «Обновление»: четыре карточки


Все обновления собраны в одном разделе. Сверху — кнопка **«Проверить всё»**:
она запускает четыре проверки сразу и показывает сводку по каждой.

### Карточка 1. Запрет (Flowseal)

Проверяется последний релиз `Flowseal/zapret-discord-youtube`; `.zip`-архив
скачивается и распаковывается в папку запрета с заменой файлов. Если служба
была запущена, она останавливается на время обновления и запускается заново.
**Пользовательские списки** (файлы, в имени которых есть `-user.`) не
перезаписываются.

### Карточка 2. Интерфейс (Zapret GUI)

Показывает текущую версию `config.APP_VERSION` и версию последнего релиза
`Taxousq/Zapret-GUI`. Кнопка **«Обновить»** открывает диалог, скачивает
`ZapretGUI-Setup-*.exe` и запускает его: приложение закрывается, установщик
ставит новую версию. В релизе без установщика обновление не предлагается —
такой релиз только пишется в журнал.

### Карточка 3. Cloudflare WARP

Показывает версию установленного клиента (`warp-cli --version`, при
недоступности — версия из реестра Windows) и подпись «Обновляется
автоматически через Cloudflare». Кнопка **«Проверить обновление»** спрашивает
у `winget`, есть ли версия новее:

```bat
winget upgrade --id Cloudflare.Warp --accept-source-agreements
```

Скачивания и установки здесь нет: WARP обновляет себя сам. Если `winget` в
системе нет, кнопка проверки неактивна, а вместо неё работает **«Открыть
сайт»** — страница загрузки Cloudflare. Если WARP не установлен, карточка
показывает «не найден» и обе кнопки неактивны (ставится WARP отдельно, раздел
«Обход (WARP)» управляет уже установленным клиентом).

### Карточка 4. TG WS Proxy (Flowseal)

Проверяется последний релиз `Flowseal/tg-ws-proxy` через GitHub API; из ассетов
берётся `.exe` (часть имени — `windows`, окончание — `.exe`), скачивается в
`%TEMP%\ZapretGUI-tgws-update`. Архива здесь нет: TG WS Proxy поставляется
готовым exe, поэтому файл просто кладётся на место старого.

**Перед заменой процесс закрывается** — `taskkill /IM TgWsProxy_windows.exe /F`
(с подтверждением пользователя: на время обновления Telegram теряет связь).
Старый exe сначала отводится в `.bak`, и если скопировать новый файл не
удалось, он возвращается на место. **После замены приложение не запускается
автоматически**: обновлённый exe запускает пользователь кнопкой «Запустить».
Раньше автозапуск давал второй экземпляр и модальное окно самого прокси
«Приложение уже запущено, проверьте трей». По той же причине
`TgwsManager.start()` не стартует процесс, если он уже работает.

**Версию установленного приложения определить не всегда возможно**: у сборок
Flowseal нет флага `--version`. В этом случае карточка пишет «Доступна версия X
с GitHub. Версию установленного приложения определить не удалось — нажмите
«Обновить», чтобы поставить её принудительно» (серый уровень), а кнопка
«Обновить» остаётся активной. Ложных уведомлений нет.

## Первый запуск: где взять запрет


Запрет GUI **не поставляет**: это отдельный проект, который живёт своей
жизнью и обновляется отдельно. Путь к папке запрета настраивается в GUI и
хранится в настройках приложения — править код не нужно.

**Автопоиск.** При первом запуске приложение ищет запрет в таком порядке:

1. путь службы `zapret` из реестра (`HKLM\SYSTEM\CurrentControlSet\Services\zapret`,
   параметр `ImagePath`) — если служба уже установлена, папка находится точно;
2. подпапки с именем на `zapret` в типичных родительских каталогах (`D:\`,
   `C:\`, `%USERPROFILE%`, `%LOCALAPPDATA%`, `%ProgramFiles%`, «Загрузки»,
   «Рабочий стол») — так находится папка вида `zapret-discord-youtube-1.9.2`;
3. `D:\Zapret` (исторический путь);
4. `C:\zapret`;
5. папка `zapret` рядом с приложением и на одном уровне с ней;
6. `%USERPROFILE%\zapret`;
7. `%LOCALAPPDATA%\zapret`;
8. `%ProgramFiles%\Zapret`;
9. `zapret` в «Загрузках», на «Рабочем столе» и в «Документах»;
10. `zapret` в корне каждого локального диска;
11. `zapret` рядом с exe в portable-режиме (флешка).

Папка считается запретом, если в ней есть `service.bat` **или** `bin\winws.exe`
**или** хотя бы один `general*.bat`. Найденный путь сохраняется в настройках.

**Мастер первого запуска.** Если запрет не найден, открывается модальное окно
«Первый запуск» с **пятью** кнопками:

* **Скачать с GitHub** — выбираете папку, приложение скачивает последний релиз
  Flowseal (через GitHub API) с прогресс-баром и распаковывает его. Служба при
  этом **не** устанавливается: после скачивания приложение скажет
  «Запустите `service.bat` от имени администратора и выберите `Install Service`.
  После этого нажмите OK»;
* **Указать папку вручную** — обычный диалог выбора папки; выбранная папка
  проверяется, при ошибке показывается «Эта папка не похожа на запрет.
  Убедитесь, что там есть service.bat или bin\winws.exe»;
* **Искать везде** — полный обход локальных дисков (до трёх уровней вложенности,
  системные папки пропускаются). В строке состояния видно, какая папка
  проверяется сейчас. Операция долгая, поэтому запускается только по нажатию;
* **Остановить** (`stop_button`) — видна **только во время обхода** и заменяет
  собой «Отмену»: прерывает поиск и возвращает мастер в обычный вид, не
  закрывая его;
* **Отмена** — приложение всё равно запускается, но в ограниченном режиме:
  в статус-баре написано «Запрет не найден», а разделы «Стратегии» и
  «Тестирование» показывают подсказку «Укажите папку в Настройках».

**Где хранится путь.**

* обычный режим — реестр: `HKEY_CURRENT_USER\Software\ZapretGUI\Paths`, ключ `zapret_path`;
* portable-режим — `config.ini` рядом с exe.

**Сменить путь после первого запуска** можно в разделе **«Настройки»**:
«Изменить папку», «Проверить папку», «Скачать заново с GitHub». После смены
пути список стратегий перечитывается автоматически.

## Как это работает


### Служба, а не процесс

Запрет ставится как обычная служба Windows, поэтому GUI работает через
`sc.exe` (`query` / `start` / `stop` / `delete` / `create`) и `reg.exe`.
Статус определяется по выводу `sc query zapret`:

| Вывод | Состояние в интерфейсе |
|---|---|
| `RUNNING` | Работает (зелёный) |
| `STOPPED` | Остановлена (красный) |
| код `1060` (служба не установлена) | Не установлена (серый) |

Если папка запрета не найдена или не похожа на запрет, приложение вообще не
опрашивает службу: в статус-баре видно «Запрет не найден», а разделы
«Стратегии» и «Тестирование» предлагают указать папку в «Настройках».

Кодировка вывода Windows-команд — **cp866** (русская Windows). Приложение
декодирует вывод как UTF-8, а при неудаче — как cp866/cp1251: часть `.bat`-файлов
запрета переключает консоль в UTF-8 (`chcp 65001`), и жёсткое cp866 превратило бы
русский текст в кракозябры.

### Стратегии

Стратегии — это `.bat`-файлы в корне папки запрета. Имя стратегии извлекается
регулярным выражением `general\s*\(([^)]+)\)\.bat`, поэтому `general (ALT11).bat`
даёт стратегию `ALT11`. Файл `general.bat` тоже попадает в список под именем
`general`. Служебные файлы (`service.bat`, `uninstall.bat`, `kill-windivert.bat`)
пропускаются. Сортировка: сначала `ALT11` и `ALT12`, затем остальные `ALT*`
по номеру, затем все прочие по алфавиту.

Текущая стратегия установленной службы читается из реестра —
`HKLM\SYSTEM\CurrentControlSet\Services\zapret`, параметр
`zapret-discord-youtube` (именно туда её пишет `service.bat`).

### Установка стратегии

Файлы стратегий сами службу не создают: они запускают `winws.exe` отдельным
процессом. Службу создаёт `service.bat`, разбирая выбранную стратегию и передавая
её аргументы в `sc create`. Интерактивное меню `service.bat` (`set /p` + `pause`)
для GUI непригодно, поэтому тот же разбор повторён в
`core/service_manager.py::build_winws_args`:

1. из `.bat`-файла читается строка запуска `winws.exe`;
2. подставляются переменные батника (`%BIN%`, `%LISTS%`, `%GameFilterTCP%` и др.);
3. токены склеиваются по тем же правилам, что и в `service.bat`
   (`--arg=value` → `--arg value`, значения с путями берутся в кавычки);
4. служба удаляется, выжидается 2 секунды, затем `sc create` с полученными
   аргументами, `sc description`, запись имени стратегии в реестр и `sc start`.

Результат разбора проверен сравнением с фактическим `ImagePath` установленной
службы — совпадает посимвольно.

### Скачивание запрета

Раздел «Настройки» и мастер первого запуска используют
`core/zapret_locator.py::ZapretLocator.download_from_github`, который опирается
на `core/updater.py`: GitHub API `releases/latest` → `.zip`-ассет → временная
папка → распаковка. Архивы релизов бывают с корневой папкой и «плоские» —
если внутри одна папка (не `bin`/`lists`/`utils`), её содержимое и становится
папкой запрета, поэтому лишнего уровня вложения не появляется.

Если папка-приёмник уже не пуста, файлы распаковываются поверх (существующие
файлы с такими же именами заменяются). Пользовательские списки (`*-user.*`)
при **обновлении** не перезаписываются — см. раздел «Обновление».

### Тестирование стратегий

Раздел «Тестирование» работает **своим** тестером (`core/strategy_tester.py`):
встроенный `utils\test zapret.ps1` не запускается. Он требовал удаления службы
перед тестом, печатал непонятные статусы (`TLS1.2:OK`, `TLS1.3:UNSUP`) и ругался
на домены, которые на самом деле работают (`YouTubeWeb: HTTP:SSL`).

Проверяются **те же сайты**, что и в «Проверке связи» (YouTube, Discord,
Instagram, Telegram, Google):

* **HTTP** — запрос через `requests` (сначала `HEAD`, при `405`/`501` — `GET`
  со `stream=True`), таймаут 10 секунд, User-Agent и заголовки как у Chrome;
* **TLS** — HTTPS-соединение считается рабочим, если запрос дошёл до ответа;
* **ICMP** — `ping -n 1` с таймаутом 5 секунд. Пинг — дополнительная проверка:
  если ICMP блокируется, в таблице будет «—», и это **не** провал.

Два режима:

| Кнопка | Что делает | Время |
|---|---|---|
| **Проверить текущую** | Проверяет стратегию, с которой запущена служба. Служба не переключается и не удаляется | 5-10 секунд |
| **Тестировать все** | По очереди переустанавливает службу с каждой стратегией и заполняет таблицу | 3-5 минут |

Перед перебором запоминается стратегия, с которой служба работала до теста, и
**после теста возвращается** — в том числе если тест прерван кнопкой
«Остановить». Кнопка «Применить лучшую» устанавливает стратегию с наибольшим
числом доступных сайтов (при равенстве — с меньшим пингом). Лучшая стратегия
подсвечена в таблице зелёным.

Статусы в таблице:

| Ячейка | Значение |
|---|---|
| `OK` (зелёный) | Сайт ответил: 2xx/3xx |
| `HTTP 401` / `HTTP 403` / `HTTP 429` (зелёный) | Сайт блокирует автоматические запросы, но соединение работает — сайт **доступен** |
| `FAIL` (красный) | Ответ 5xx, таймаут 10 секунд или обрыв соединения |
| `?` (жёлтый) | Ошибка TLS — «неопределено», провалом не считается |
| «—» в колонке «Средний пинг» | ICMP недоступен (не провал) |

Тест идёт в фоновом потоке, поэтому интерфейс не подвисает, а вывод тестера
виден в журнале под таблицей. Если ни одна стратегия не работает, раздел
предлагает проверить интернет и настройки.

### Проверка доступности

Сайты проверяются параллельно (`ThreadPoolExecutor`, 5 потоков), таймаут 10 секунд
на сайт, User-Agent и заголовки (`Accept`, `Accept-Language`) как у Chrome. Сначала
отправляется `HEAD`; если сервер метод не поддерживает (`405`/`501`), запрос
повторяется через `GET` со `stream=True` — тело страницы не вычитывается.

Доступным считается **любой ответ ниже 500**: даже 401/403 от YouTube и Instagram
означают, что сайт блокирует автоматические запросы, но соединение установилось и
блокировка обходится. Ошибкой считается только `5xx` и неудачное соединение.

В строке сайта показывается конкретная причина: `HTTP 403`, `Timeout 10s`,
`SSL error: …`, `Connection error: …`, `Proxy error: …`, `DNS error: …`.

Проверка идёт в фоновом потоке, так что интерфейс не блокируется, а фактическое
время отклика и причина показаны рядом с сайтом.

| Статус | Значение |
|---|---|
| `OK` | Сайт ответил: 2xx/3xx/401/403/429 (зелёная точка и зелёная причина) |
| `FAILED` | Сервер ответил 5xx (красная) |
| `TIMEOUT` | Нет ответа за 10 секунд (жёлтая) |
| `ERROR` | TLS, прокси, DNS или обрыв соединения (красная) |

### Обновление

Раздел «Обновление» — один экран на четыре источника. Для запрета используется
GitHub API `releases/latest`, из ассетов берётся `.zip`. Архив скачивается во
временную папку, распаковывается и копируется в папку запрета с заменой файлов.
Если служба запущена, перед обновлением она останавливается (иначе `winws.exe`
заблокирован) и запускается заново после.

Сам GUI обновляется установщиком из релизов `Taxousq/Zapret-GUI`
(`core/app_updater.py`), а Cloudflare WARP только проверяется через `winget`
(`core/warp_updater.py`) — он обновляет себя сам.

**TG WS Proxy обновляется иначе** (`core/tgws_updater.py`): архива у него нет —
из релиза скачивается готовый exe (`windows` в имени, `.exe` на конце), и он
кладётся на место старого. Перед заменой процесс закрывается через
`taskkill /IM TgWsProxy_windows.exe /F` (с подтверждением пользователя: Windows
не даст перезаписать занятый файл), старый exe отводится в `.bak` и возвращается
на место, если копирование сорвалось, а после удачной замены приложение
запускается заново.

**Пользовательские списки** (`list-*-user.txt`, `ipset-*-user.txt` и любые файлы,
в имени которых есть `-user.`) не перезаписываются, чтобы не потерять ваши правки.

### Автозапуск

Чекбокс «Запускать Zapret GUI при входе в систему» создаёт ярлык в
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`. Ярлык создаётся через
COM-объект `WScript.Shell` средствами PowerShell — это **не требует pywin32**.
При запуске из исходников целью ярлыка является `pythonw.exe` (без окна консоли),
в собранной версии — сам `ZapretGUI.exe`. Если PowerShell недоступен, создаётся
резервный `.cmd`-файл.

### Логи

Записи читаются через `wevtutil`: сначала журнал `Application` с фильтром по
поставщику `zapret`, затем (если пусто) журнал `System` с фильтром по
`Service Control Manager`, из которого выбираются записи, упоминающие `zapret`.
Если записей нет — показывается подсказка: `winws.exe` в журнал Windows не пишет,
и это нормально.
